## 一、竞品在微信内的分发形态

### 1. 公考雷达（gongkaoleida.com，直接对标）
- **形态：App 为主 + 微信公众号（推送/互动）+ Web，官方渠道未见独立小程序主打**。官网下载页明确写「人性化职位定制和动态提醒，微信、APP、PC 多终端及时送达」「关注微信公众号 领取限量公考礼包」（实测，见截图 assets/r290/gkld-download.png）。
- **入口与转化路径（实测 + 官方页面描述）**：
  1. 公众号「公考雷达」：公告推送 → 图文内嵌 App 下载/H5 链接 → 引导装 App（礼包钩子：关注领「限量公考礼包」）；
  2. H5 移动站（实测截图 assets/r290/gkld-home.png）：首页即「今日发布考试资讯 N 个 + 分省近七日新增」数字焦虑驱动，核心功能（订阅提醒、报名大数据）均要求登录/装 App；
  3. App Store 介绍自述渠道矩阵：官网 + 微信公众号 + 小红书官方号。
- **要点**：它的微信策略是「公众号做提醒触达 + H5 做承接 + App 做留存」，与我们「Web push 提醒」定位同构，但它的提醒走公众号模板消息/图文推送，在微信内无摩擦。

### 2. 国聘（iguopin.com，国投人力官方）
- **形态：全家桶——官网/H5 + App + 微信小程序 + 公众号/视频号 + 抖音/快手/B站/小红书官方矩阵**。其声明称「国聘在微信公众号及视频号、抖音、快手、哔哩哔哩、小红书等新媒体平台均有官方账号」（来源：https://mp.weixin.qq.com/s/nwfHcCrrYj2lFlTliqFkBA ）。
- H5 首页为重 JS 单页，移动 UA 下首屏长时间「加载中…」（实测截图 assets/r290/iguopin-home.png，加载 20s 仍为骨架）——大厂 H5 体验并不佳，主要靠 App/小程序承接。
- 传统人才网「国聘人才网 guopin.com.cn」有专门小程序落地页，卖点即「无需下载安装，关联后直接使用」「小程序可以被便捷地获取和传播」。
- **要点**：小程序的核心价值 = 微信内一键打开 + 卡片式分享传播（分享出去是小程序卡片而非链接）。

### 3. 职引（zhiyincareer.com，2024 创业公司）
- **形态：Web 优先 + AI 工具（简历优化/模拟面试/岗位匹配）**，公开资料未见成规模微信小程序/公众号运营（推断：与我们同处「有产品无分发」阶段）。参考价值低于前两者。

### 4. 公考培训机构（粉笔/中公/华图）
- **公众号是绝对主阵地**：新榜矩阵报告显示中公公众号活跃账号占比 70.8%、华图 58.9%，矩阵结构为「品牌旗舰号 + 专业科目号 + 区域服务号」（来源：https://matrix.newrank.cn/article/article-detail/8cb32ed83f434e83 ）。
- 粉笔：App + 小程序 + 公众号 + 社群构成私域矩阵，用 H5 裂变活动（助力答题、拼团、砍价）持续拉新（来源：https://www.36dianping.com/case/13543 ）。
- **要点**：面向考公人群，微信系（公众号+社群+小程序）是行业公认主战场；机构靠「免费资料/礼包 → 关注 → 社群 → 课程转化」漏斗。

## 二、自家 H5（jobs.zalize.com）在微信内的实际体验

### 2.1 分享卡片现状
- **HTML 层（实测 curl）**：首页有完整 og:title/og:description/og:image/og:site_name；og:image 用的是 `apple-touch-icon.png`（180×180，15.7KB）。
- **SSR 内容页缺 OG**：`/daily`、`/rank/*`、`/province/*` 有独立 `<title>` 但**无 og: 标签**（/province 返回 SPA 壳的默认 OG）；`/topic/*` 直接 404（`/topic/guangdong-benke` 实测标题「页面不存在」——专题页 slug 需以站内真实 slug 为准，但说明深链健壮性待查）。
- **微信内实际卡片（推断，依据微信官方文档）**：微信聊天中分享 H5 链接，**不读取 OG 协议**；未接入微信 JS-SDK 的页面，卡片默认取 `<title>` + 页面截取摘要 + 抓取页内图片（SPA 常抓不到 → 灰色链接图标）。即我们的卡片大概率是「上岸雷达 - 全国体制内岗位检索 + 无图/默认图」，朋友圈则退化为纯文字链接。自定义卡片必须 `wx.config` + `wx.updateAppMessageShareData`（来源：https://developers.weixin.qq.com/doc/service/guide/h5/jssdk ），前置条件为**认证服务号 + JS 接口安全域名备案**——代码库实测无任何 `jweixin/wx.config` 接入。

### 2.2 微信内置浏览器不可用能力（实测代码 + 官方文档推断）
| 能力 | 现状 | 微信内 |
|---|---|---|
| Web Push 提醒（我们的核心留存功能） | SW + Push API | **不可用**（微信内置 X5/XWeb 不支持 Push API；且 iOS Web Push 仅 Safari 加桌） |
| PWA 安装（InstallAppEntry 组件） | beforeinstallprompt | **不可用**，微信无「添加到桌面」PWA 通道 |
| navigator.share 系统分享 | ShareTextButton 已有 | 微信内多不可用，回退复制链接 |
| 二维码分享（qrcode 生成深链） | 已有 ✅ | 可用，微信长按识别 ✅ |
| 复制链接 | 已有 ✅ | 可用 ✅ |

### 2.3 最小改造清单（微信体验）
1. 全站 SSR 页面（/daily、/rank、/province、/major、/topic）补齐 og:* + 更大尺寸分享图（≥300×300，岗位数/日期动态文案图更佳）——微信外渠道（QQ、微博、Telegram、搜索引擎）和站外爬虫都读 OG，成本极低；
2. 微信 UA 检测（`MicroMessenger`）：隐藏 PWA 安装/推送引导，替换为「二维码保存 + 收藏到微信浮窗提示 + 复制链接去浏览器打开」引导条；
3. 分享卡片 JS-SDK 接入依赖认证服务号（见 §四老板资源清单），在此之前用「生成分享图（岗位卡截图式 PNG）+ 二维码」替代——用户转发图片到群，长按识别即达，绕开链接卡片难看的问题。

## 四、改造清单

### 不需要老板资源的 Top3 自助改造（按 ROI 排序）
1. **SSR 页面族补 OG + 动态分享图（ROI 最高）**：/daily /rank /province /major /topic 补 og:title/desc/image；用后端生成 1200×630 与 300×300 两档 PNG（站名+岗位数+日期）。要点：SSR 模板改动 + 一个 Pillow/canvas 出图端点 + CDN 缓存；顺手修 /topic 深链 404 兜底。受益面：微信外全渠道分享 + 搜索富摘要。
2. **微信 UA 适配 + 「图片式分享」**：检测 MicroMessenger 后：a) 隐藏推送/PWA 引导（现在是死入口，浪费首屏）；b) 分享菜单增加「生成分享图」——岗位卡样式 PNG（标题/单位/学历/截止日 + 站点二维码），转发群聊长按识别直达。要点：复用现有 qrcode 依赖 + html2canvas 或后端出图。
3. **知乎/B站/小红书「盘点内容 → 落地页」流水线**：把已有 /topic、/rank/shangan、/daily 数据自动生成周更「XX 省本科可报岗位盘点」图文素材（Markdown + 配图），人工 5 分钟/篇发布；知乎简介+回答尾链、B站简介直链、小红书评论区置顶引导群聊。要点：脚本产素材入 exports/，UTM 参数区分渠道，周复盘 PV。

## 五、结论（SOP-04）

- **结论**：考公人群分发主战场在微信系（竞品全部以「公众号提醒 + App/小程序承接」为核心漏斗）；我们的 H5 在微信内是「二等公民」——分享卡片不可控、核心留存功能（Web push/PWA）全部失效。不依赖老板资源可先做 OG/分享图/微信 UA 适配 + 内容盘点导流三件事；微信内提醒闭环（服务号模板消息）是需要老板掏 300 元/年 + 企业主体的最高杠杆项。
- **证据**：本报告 §一–§四 内文链接与 `docs/research/assets/r290/` 截图（gkld-home/gkld-download/iguopin-home/own-home/own-daily）。
- **下一步**：建议 R291+ 迭代侧落地 Top3 之 1（SSR OG + 动态分享图）与之 2（微信 UA 适配）；老板侧一次性申请：认证服务号 + 搜索站长验证授权。
- **需注意**：微信内渲染细节为文档推断，接服务号后需真机回归；平台导流规则（尤其小红书）随时收紧，执行时以小号先试。
